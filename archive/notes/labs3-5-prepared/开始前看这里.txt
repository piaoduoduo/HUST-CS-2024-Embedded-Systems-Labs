准备内容
common/graphic.c：保留实验二实现；补齐 JPG、透明 PNG、字模三种图像绘制。
  RGB8880 行拷贝；RGBA8888 逐通道混合；ALPHA8 使用参数 color 着色。
  使用每行 line_byte，支持负坐标与四边裁剪，使用 /255 并四舍五入确保透明度端点准确。
common/image.c：沿用课程解码库和字体代码，修正子图片把高度误写成宽度的检查及分配大小计算。
lab3/main.c：保留课程示例构图，检查图片/字模加载失败；首行基线改为70，防止64像素文字超出上边界。
common/touch.c、touch_protocol.c/h：读取协议B多点触摸，以 SYN_REPORT 汇总事件，查询真实坐标范围，最多处理五指。
  可自动查找支持 SLOT、MT_POSITION_X/Y 的设备，也可指定 --touch。事件队列须由回调循环读完。
  若驱动报告 SYN_DROPPED，会提示重新启动实验以恢复同步；不会继续使用丢失后的旧触点。
lab4：五指五色、直径9像素圆形笔刷、插值连续轨迹、顶部清屏按钮。
  清屏时仍按住的手指需抬起后才能重新画，避免清屏后立刻被旧轨迹覆盖。
lab5_bt：原始模式串口，非阻塞收发，send按钮发送 hello\n，收到的文本显示于屏幕并输出到终端。
  UTF-8可跨多次read接收；支持CRLF、没有换行的短消息、长文本分段显示和发送短写重试。
  不完整UTF-8会等待后续字节；错误字节替换为问号。断开后重新连接RFCOMM并重新运行程序。
test：保留课程综合性能测试，扩大计时数字缓冲区，避免超过4位数时溢出。
out：完整课程 test.jpg、test.png、font.ttc。

下次上板的顺序
1. 开发板/显示屏供电、HDMI和触摸USB线接好，电脑与开发板通过网线连接。
2. 重新确认开发板IP。上次地址是192.168.137.115，不能假定重启后仍相同。
3. 登录SSH，确认是 root@orangepi4-lts 提示符。以下Linux命令均在开发板执行。
4. 先确认板上日期。此前镜像的时间停留在2022年；校正时间后再编译，避免make时间警告。
5. 按PPT37～38页停止“开发板的Ubuntu桌面”。Windows桌面、电脑上的Codex和向助手提问不受此设置影响。
   PPT流程为 orangepi-config -> System -> Desktop -> Stop -> reboot。
   重启后需要重新确认IP并登录。完成上述过程前，本包不会替你自动禁用桌面。
6. 上传并在Linux解压 labs3-5-ready.tgz，不要把Windows解压出来的原课程目录替代板上的完整课程包。
   原课程 external/lib 中有符号链接，应保留实验一在Linux解压得到的目录。

实验五（先配置和连接，再运行应用）
1. 查看实际状态和工具：
   systemctl cat bluetooth
   systemctl status bluetooth --no-pager
   hciconfig
   bluetoothctl show
   command -v rfcomm sdptool bluetoothctl hciconfig
2. 按PPT80页检查bluetoothd是否带-C兼容标志，以及是否注册SP串口服务。
   本包 bluetooth-rfcomm.conf.example 仅为待核对的配置样例；先确认实际二进制路径和原有启动参数。
   若需要修改，使用systemd drop-in，备份原有配置；不要盲目覆盖整份系统unit文件。
   应用修改需要 systemctl daemon-reload 和重启 bluetooth 服务；这些操作目前都尚未执行。
3. 进入 bluetoothctl，按PPT81页配对。可使用下列命令：
   power on
   agent on
   default-agent
   system-alias HUST-LAB-你的标识
   pairable on
   discoverable on
   scan on
   scan off
   pair 对端MAC
   trust 对端MAC
   配对提示需要在实际手机或电脑上确认。不要把示例MAC当作真实设备。
4. 保持两个SSH终端：
   终端A运行 rfcomm -r watch 0 1，保持该窗口运行。
   安卓手机蓝牙串口SPP程序或Windows串口客户端连接开发板的串口服务（PPT85页）。
   iPhone路线按PPT说明优先改用Windows蓝牙串口客户端。具体客户端稍后按实际设备选择。
   配对本身还未建立/dev/rfcomm0，必须由客户端实际连接RFCOMM服务后再继续。
5. 终端B执行：
   python3 "$prepared_dir/preflight.py" --project "$project_dir" --lab lab5_bt
   bash "$prepared_dir/run-lab.sh" "$project_dir" lab5_bt
   必要时加 --touch /dev/input/eventN。
6. 双向验收：
   对端发送英文、中文或数字，开发板屏幕和终端均能看到。
   点击开发板屏幕右上send，对端收到hello。
   多发几次、发送多行/较长文本，确认不会乱码、卡死或覆盖按钮。
   只有配对成功不算收发验收通过，必须保留实际双向通信记录。
7. 如仅排查软件串口路径，可在Linux执行预备的伪终端集成测试：
   python3 "$prepared_dir/tests/board-serial-test.py" --binary "$project_dir/out/lab5_bt"
   该测试不需要蓝牙连接，也不验证无线链路，不能替代正式实验五验收。
8. 结束后Ctrl+C退出程序和rfcomm监听，并在bluetoothctl中执行 discoverable off、pairable off。
