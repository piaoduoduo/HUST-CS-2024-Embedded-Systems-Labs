三、连接失败时按顺序排查
以下第一组在电脑的 Windows PowerShell 执行：
  ipconfig
  Test-NetConnection 192.168.137.115 -Port 22
检查与开发板相连的以太网是否已连接，IPv4 是否为192.168.137.1。
TcpTestSucceeded=True 表示能访问开发板 SSH 端口。
多网卡环境下，可尝试指定电脑以太网地址：
  ssh -b 192.168.137.1 root@192.168.137.115

如果电脑以太网地址不对：
Windows 按 Win+R，输入 ncpa.cpl，打开网络连接。
WLAN 属性 → 共享 → 勾选允许其他网络用户通过此计算机的 Internet 连接来连接。
家庭网络连接选“以太网”（连接开发板的那一个），点确定，再检查 ipconfig。
先检查网线两端是否插紧，必要时电脑端拔下等5秒再插紧。

如果还连不上，开发板终端执行以下命令，检查 eth0 的完整一行：
  ip -4 -br addr
期望：eth0 为 UP，并有 192.168.137.115/24。
特别注意是192.168，不能写成192.16。
若没有正确地址，可临时恢复：
  sudo ip addr replace 192.168.137.115/24 dev eth0
如果出现误填的192.16.137.115，应在确认正确地址存在后清理误填地址。
这条 ip addr 命令只对当次开机生效。
本次已经把 Wired connection 1 保存为手动192.168.137.115/24，
并设置 never-default，所以下次应先检查该保存配置是否生效。

补充：arp -a 没有条目不能单独证明网线或开发板坏了。
本次 DHCP 未取得可用地址时，反复扫描无效；修正开发板地址后 SSH 立即恢复。
板上 USB 网卡 usb0 的192.168.1.2是另一条连接路线，不能当成网线接口地址。

四、连上后，为实验三、四、五准备屏幕
以下全部在 root@orangepi4-lts 的开发板 SSH 终端执行：
  ip -4 -br addr
  date -Is
  systemctl is-active display-manager
  fbset -i
  cat /proc/bus/input/devices

如果开发板桌面处于 active，先临时停止：
  systemctl stop display-manager
小屏幕暂时变黑是正常现象，接着运行实验程序即可。
这会停止开发板上的 Ubuntu 桌面，不影响笔记本 Windows、Codex 或聊天。
本次没有把开机默认 graphical.target 改掉，重启后桌面可能会恢复。

课程程序使用1024×600、32位颜色。
本次桌面虽是1024×600，但 framebuffer 最初仍为1280×720。
停止开发板桌面后，以下调整已验证有效：
  fbset -g 1024 600 1280 720 32
这条命令用于本次遇到的1280×720虚拟缓冲模式；下次先查看 fbset -i 再决定。
调整后 fbset 的 geometry 前两项应为1024 600。
虚拟尺寸仍可能是1280×720，行跨度5120字节，这是本次通过验证的正常状态。
不能仅根据 /sys/class/graphics/fb0/virtual_size 判断可见画面是否错误。
触摸设备需在 /proc/bus/input/devices 中寻找 wch.cn USB2IIC_CTP_CONTROL，
上次是 event2，原始X/Y范围0～4096，程序会自动缩放。
